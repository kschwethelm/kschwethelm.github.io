Abstract

A main promise of looped language models is depth-adaptive inference. By looping a block of shared layers a variable number of times, the model can use less compute for “easy” tokens and more for “hard” ones. However, tokens with different numbers of loops cannot share a uniform forward pass and therefore cannot be handled by standard batching systems such as vLLM. The practical value of depth-adaptive inference thus hinges on whether batching can be made efficient.

We introduce the first efficient method for depth-adaptive looped LMs via continuous depth batching (CDB), which forms new batches between loop steps. Our method dynamically schedules looped and non-looped parts of the architecture, manages looped KV-caching, and predicts which tokens will exit the loop in advance so it can prepare batches asynchronously.

Experiments on Ouro 1.4B and Huginn 3.5B show that fully looped architectures are best suited to depth-adaptive inference, as large non-looped layers outside the recurrent core (e.g., token embedding, LM head, and unshared transformer blocks) slow down and complicate scheduling. Overall, CDB realizes up to 99% of the estimated maximum speedup available, leaving further gains primarily dependent on model architecture and exit behavior.

What is depth-adaptive decoding?

Looped LMs repeatedly execute a block of shared layers, called the recurrent core, to scale effective computation with loop steps without increasing parameter count. Outside the recurrent core, unshared layers in the prelude and coda process each token before it enters the loop and predicts the next token after exiting the loop, respectively.

Depth-adaptive decoding allows tokens to exit the recurrent core after different depths (different number of loop steps). The model can use fewer loops and less compute for “easy” tokens, and more loops for “hard” ones, improving the compute–accuracy trade-off. But can we serve these dynamic forward passes efficiently?

Problem: Batching tokens with different forward passes

In depth-adaptive decoding, tokens within a batch can have different numbers of loops and thus different forward passes: exited tokens need to run the coda, while remaining tokens need another loop step. Standard serving systems like vLLM assume a uniform forward pass and cannot batch these tokens together. Our inference method based on continuous depth batching (CDB) can do it by forming new batches between loop steps within the forward pass and refilling batch slots as tokens exit.

We propose three components to make this efficient:

Stage-wise scheduling

Exited tokens need to run the coda, while remaining tokens need another loop step. Our scheduler decides which stage to run next and batches its waiting tokens. It interleaves prefill, prelude, core, and coda to refill freed slots and keep batch size high.

Depth-aware KV cache

Our cache manager handles the missing KV states left by early exits. Last-exited maps skipped depths to the final KV state and returns their slots to the cache pool. Shared caching updates one slot per token and recurrent layer at each loop step.

Lookahead gate

With standard early exit gates, the CPU must wait for the exit decisions after each loop step. It then prepares the next batch while the GPU is idle. Our lookahead gate predicts exits one loop step earlier, so batch preparation overlaps GPU execution.

Main findings

To analyze CDB, we derive a prefill-corrected bound that estimates the maximum achievable speedup and a hardware-aware latency model that predicts when refill helps. We then evaluate CDB in offline throughput and online serving benchmarks on two prominent looped models with different architectures: Ouro is fully looped, while Huginn loops only its middle transformer block with non-looped blocks in prelude and coda.

We make the following main findings:

Depth-adaptive decoding can be served efficiently

Our CDB implementation solves the batching problem posed by variable-depth forward passes. CDB with refill is near-optimal for fully looped models and can realize up to 99% of the speedup available from early exits.

Co-designing looped LMs and inference systems is important.

Our results offer concrete guidance for designing looped models that benefit even more from depth-adaptive inference: cheap prelude and coda, lookahead exit decisions, and memory-efficient KV cache support.

Improved the compute-accuracy trade-off

CDB preserves the model’s predictions and exit decisions. However, early-exits and KV cache sharing affect accuracy. Meaningful speedups require models like Ouro that provide enough early exits at the desired accuracy.
